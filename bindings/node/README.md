# @polyjose/node

polyjose for Node.js: JOSE (JWS, JWE, JWK and JWT; RFC 7515 to 7519) implemented in pure Rust and
loaded as a Node-API addon. All cryptography comes from the RustCrypto and dalek crates, with no
OpenSSL. Verify and decrypt always take an explicit algorithm allow-list, and `none` is never
accepted (RFC 8725).

> Status: **pre-alpha**. Don't use it in production yet.

## Install

```sh
npm install @polyjose/node
```

npm also installs the matching prebuilt addon, `@polyjose/node-<platform>`, for macOS (x64,
arm64), Linux glibc and musl (x64, arm64) and Windows (x64, arm64).

## Module format

- The package is **ESM only** and needs **Node.js 22.12 or later**.
- CommonJS code can still load it with `require("@polyjose/node")`, through Node's `require(esm)`
  (unflagged since 22.12).
- Every operation returns a Promise. The work runs on the libuv thread pool, so it doesn't block
  the event loop.
- The API and its TypeScript types are the same as `@polyjose/wasm`, so you can switch between
  the two packages by changing the import.

## Documentation

Guides and the API reference are at <https://polyjose.dev>. The Node.js guide is at

## Loading the addon

The loader (`binding.cjs`, generated by napi-rs) picks your platform's addon: first a local
`polyjose.<platform>.node` next to it, then the platform package `@polyjose/node-<platform>`. It
resolves both against its own directory, never the working directory. The package wraps the
loader so that it loads **only the native addon** and fails closed otherwise:

- After loading, the package checks that the result is the native addon at this package's
  version. A mismatched `@polyjose/node-<platform>` makes the import throw, whatever
  `NAPI_RS_ENFORCE_VERSION_CHECK` says. The loader alone checks the platform package's version
  only when that variable is set to something other than `0`.
- polyjose **never publishes a `wasm32-wasi` package**. The loader napi-rs generates still has a
  WASI fallback, tried when the native load fails: `./polyjose.wasi.cjs`, then
  `@polyjose/node-wasm32-wasi`. The package never reaches it. If the native load fails, the import
  throws "Cannot find native binding". If either WASI file or package can be found from the
  loader's directory, the import throws before anything is loaded. For WebAssembly, use
  `@polyjose/wasm`.

### Environment variables

| Variable | Effect |
|---|---|
| `NAPI_RS_NATIVE_LIBRARY_PATH` | Loads the native library at this path instead of the bundled addon. It must still be a polyjose addon of this package's version. |
| `NAPI_RS_FORCE_WASI` | **Refused.** If it is set, whatever the value (even `false` or empty), the import throws. |
| `NAPI_RS_WASI_FLAVOR` | **Refused**, like `NAPI_RS_FORCE_WASI`. |
| `NAPI_RS_ENFORCE_VERSION_CHECK` | Read by the loader for the platform package. The package checks the version anyway (see above). |

`NAPI_RS_NATIVE_LIBRARY_PATH` decides which native code handles your keys:
- If loading from that path fails, the loader doesn't fall back to the bundled addon.
- A process that can set its environment can already load native code (for example through
  `NODE_OPTIONS`), so this override doesn't widen what an attacker who controls the environment
  can do.
- Still, don't pass an untrusted environment to a process that uses polyjose, such as a container
  whose variables come from outside.

### Side effects of the generated loader

- **Linux:** to tell musl from glibc, the loader first reads `/usr/bin/ldd`. If that fails, it
  calls `process.report.getReport()`, and before that it sets `process.report.excludeNetwork = true`
  for the whole process. As a last resort it runs `ldd --version` in a child process.
- **Windows x64:** an embedder that runs Node as a shared library (`node_target_type` is
  `shared_library`), or a Node whose `shlib_suffix` is `dll.a`, is sent to the `win32-x64-gnu`
  addon only. polyjose doesn't publish that addon, so those hosts can't load the package.
- **`__napiBindingTarget`:** the loaded addon has an extra property, `__napiBindingTarget`
  (`"native"`), set by the loader. The package's own API doesn't export it.
