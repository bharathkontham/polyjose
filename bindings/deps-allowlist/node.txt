# Crates allowed in the normal dependency tree of polyjose-node (bindings/node) beyond the core's:
# what
#   cargo tree -p polyjose-node -e normal --target all --prefix none
# lists (also with --no-default-features and --all-features), other than workspace packages, crates
# of deps-allowlist.txt and crates of the core's own tree, which check 1 governs. scripts/check-deps.sh
# (check 13) enforces this file in both directions, like deps-allowlist.txt (ADR 0016 §4): a crate
# in that tree that is not listed fails, and so does an entry the tree no longer contains, or one
# that deps-allowlist.txt already allows. Adding an entry needs an ADR (ADR 0016 §4, ADR 0030 §1).
# napi-build is a build-dependency, so it is not in this tree.
#
# Format: one crate name per line; `#` starts a comment. No serde-family crate may appear in the
# tree (check 14, ADR 0030 §1: no napi `serde-json` feature) unless a `# serde-only-below:
# <crate>...` line, followed by comment lines that explain it, names the crates every path to it
# must go through. This binding has none.

# napi-rs, the Node binding's framework (ADR 0030 §1, ADR 0031): napi and its proc-macro napi-derive

# loaded through libloading and windows-link on Windows), ctor (module registration at load time),
# bitflags, nohash-hasher and rustc-hash (napi's internal tables) and the futures crates napi's
# default features use for its async task machinery (futures-util with memchr, slab and
